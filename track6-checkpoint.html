Track 6 Checkpoint: Could Someone Else Rerun Your Work?

Ten new questions you have not seen in the lessons. Each one is a real moment in a project: a leaked password, a huge data file, three files called "final", a slow conda install. Take it at the end of Track 6 to find out what you already own and what to review.

Track checkpoint ~20 min In your browser, no code

What this checks

  • You can keep secrets and large data out of Git.
  • You know what add, commit and push each do, and what GitHub protects.
  • You can organize a project so you can trace every result.
  • You know when to use conda, bioconda, mamba and containers.

Before you start

  • Finish the Track 6 lessons on the roadmap, especially Git, project organization and conda.
  • No notes on the first try. The point is to find out what you can recall, which is also one of the best ways to make it stick.

How this checkpoint works

Answer all ten questions. When you finish, the page shows your score. 7 of 10 counts as a pass; aim for 8 or more before moving on. Every explanation links to the lesson to review.

This is a self-check, not an exam. The answers live in the page, so it only works if you answer honestly before reading the explanation. If you score below 7, review the linked lessons, wait a day or two, then reload and try again. Coming back after a break helps you remember more than re-reading straight away.

The ten questions

Scenario questions. Pick the best answer; some wrong answers are tempting on purpose.

You accidentally committed a file containing an API key and pushed it to a public GitHub repo. You delete the file in your next commit. Are you safe?
Git keeps every past version, so a later delete does not erase the earlier commit. Treat any pushed secret as exposed: change it at the service that issued it. Keeping passwords and keys out of the repository in the first place is the real fix (Blischak et al. 2016; Wilson et al. 2017). Review: Git and GitHub.
You want to add your 8 GB of raw FASTQ files to your analysis repository on GitHub. What should you do instead?
Git is built for code and small text files. Hosting sites such as GitHub refuse very large files, and large data makes a repository slow to clone (Wilson et al. 2017). Deposit reads in an archive such as SRA and point to them from your README. Review: Git and GitHub.
Six months on, your folder holds final.csv, final2.csv and final_REAL.csv, and you cannot tell which one made Figure 2. Which habits would have prevented this?
A clear folder layout separates what you were given from what your code made, and version control replaces final2 and final_REAL with a history you can trace (Noble 2009). Review: Organizing a project and Git and GitHub.
Your conda environment file pins every tool version, yet a colleague on another operating system still cannot get identical results. What extra step most directly helps?
conda captures packages, but some differences come from the operating system underneath. A container packages that layer too, so the same image behaves far more consistently across machines (Nüst et al. 2020; Ziemann et al. 2023). Review: Conda environments.
Which commit message will help you most when you return to this project in six months?
A good message says what changed and why. Small commits with messages that clearly explain each change turn your history into a lab notebook you can search and trust (Wilson et al. 2017). Review: Git and GitHub.
You need samtools (a program written in C) and pandas (a Python library) in the same project. Which tool can install both into one environment?
pip and venv are built for Python packages; they cannot install standalone tools like samtools. conda manages packages from any language, and bioconda provides thousands of bioinformatics tools such as samtools (Grüning et al. 2018). Review: Conda environments.
You edited analysis.R and ran git commit, but the change does not appear on GitHub. What is the most likely reason?
The everyday loop is add, commit, push. git commit records a snapshot in your local repository; git push sends it to GitHub. (If you also skipped git add, the change was not in the commit at all.) Review: Git and GitHub.
Before your very first commit on a new computer, what do you tell Git once?
Git stamps every commit with an author name and email, so you set them once per computer. Never store passwords in files inside a repository. Review: Git and GitHub.
Your laptop is stolen. Which of your analysis work can you still recover?
Git is the tool on your computer; GitHub is the online copy. Only work that reached GitHub with git push exists somewhere else. Pushing regularly doubles as a backup. Review: Git and GitHub.
Creating a new conda environment has been "solving" for 20 minutes. What is the recommended fix from the lesson?
Older conda versions used a slow solver. Recent versions use libmamba by default, and mamba is a faster drop-in replacement for conda commands. Installing everything into base with pip is how environments get broken in the first place. Review: Conda environments.
